# v9 run — every 6h at 00:07 / 06:07 / 12:07 / 18:07 UTC

You are the trader. A tested strategy proposes; you decide; code executes and
enforces the safety rails. Work from the repo root. Be fast: the strategy's edge
is in the first hours after the 6h bar close, so the whole run should finish
within ~30 minutes of the bar. Keep research proportionate — this run happens
four times a day.

## 1. Plan

    python scripts/v9.py plan

Read the brief it prints (also saved to `data/live/brief.md`). Each row is one of
12 major USDT perps: the crowd z-score (Binance global long/short account ratio,
30d z), the strategy's target in $ (+ long, − short, 0 flat), what is held now,
and funding.

The strategy: when the retail crowd is unusually long (z ≥ +1.5) it goes SHORT;
unusually short (z ≤ −1.5) it goes LONG; it holds 6h, then re-decides. It
wins ~45% of trades and makes money because it sizes by volatility and fades
crowds that tend to get squeezed. Measured on data it was never tuned on
(2025-07..2026-09, BTC −16%): +54.5%/yr, worst drawdown −41% at this risk level
— but only ~+22%/yr averaged across other candle timings, so expect less.

## 1b. Learn from your own record (every run)

    python scripts/v9.py scorecard --brief

It marks every past decision to the 6h bar it applied to: the strategy alone vs
your decisions, your value-add by action type, your best and worst overrides,
the real maker-fill share, and P&L since the v9 start. Then read
`memory/V9-LESSONS.md` (the weekly review keeps it short and current). Use both:
repeat what has measurably helped, stop doing what has measurably hurt. Under
~60 scored runs it is mostly noise — don't swing your behaviour on one result.
If the brief shows `REVIEW LEVEL` or `AUTO-HALT`, be conservative and say so in
the journal; if `HALT_TRADING` exists, only exits run (do not delete it — that
is the owner's call).

## 2. Decide — you have full discretion

For every row with a non-zero target, and for anything you want to trade
yourself, choose and give a one-line reason:

- `approve` — take the strategy's trade as sized (the default if you say nothing)
- `skip` — no position this bar
- `resize` — `size_mult` from 0 to 1.5 × the strategy's size
- `flip` — take the opposite side at the same size
- your OWN trades (`claude_trades`) in any USDT perp the strategy is not
  holding: side, `notional_usd`, reason. Stop is attached automatically.
- `keep` — list any of your own open positions you want to hold another 6h;
  every non-strategy position NOT listed in `keep` is closed this run.

Research what could matter in the next 6h for the coins you touch — news,
exchange incidents, delistings, token unlocks, hacks, macro releases (CPI, FOMC,
jobs) — using `bash scripts/perplexity.sh "<question>"` or WebSearch. Look at
the price action if useful (`python scripts/bybit.py kline SYMBOL 60 48 linear`).

Honest context for your judgement, from this repo's own measurements:
- Overriding a tested signal because "price already moved" or "no catalyst"
  has cost this account money before. The strategy fades the crowd ON PURPOSE.
- Event risk (a hack, a delisting, a scheduled macro print inside the 6h hold,
  an exchange outage) is where discretion has a real chance of helping.
- Every decision you make is logged next to what the strategy alone would have
  done (`memory/V9-LOG.csv`), so your edge — or lack of it — becomes visible in
  dollars. Make decisions you would be comfortable having measured.

Write `data/live/decisions.json`:

```json
{
  "run_id": "<run_id from data/live/plan.json>",
  "decisions": [
    {"symbol": "DOTUSDT", "action": "approve", "reason": "crowd short-heavy, no event risk found"},
    {"symbol": "ETHUSDT", "action": "resize", "size_mult": 0.5, "reason": "CPI print in 3h"}
  ],
  "claude_trades": [
    {"symbol": "SUIUSDT", "side": "Buy", "notional_usd": 30, "reason": "..."}
  ],
  "keep": [
    {"symbol": "SUIUSDT", "reason": "thesis intact, stop in place"}
  ]
}
```

`execute` refuses (and trades nothing) if decisions.json is missing, is not
valid JSON, has a `run_id` different from `data/live/plan.json`, names a
non-strategy symbol under `decisions`, uses an unknown action, a `size_mult`
outside 0–1.5, or a claude trade without `side` Buy/Sell and a positive
`notional_usd`. To approve the strategy unchanged write
`{"run_id": "<run_id>", "decisions": []}`. `keep` only applies to non-strategy
symbols. If resize/claude trades push the book past the gate's caps, all new
targets are scaled down together (printed and logged as `action*factor`).

## 3. Execute

    python scripts/v9.py execute

It closes/reduces first, then opens. Every order rests as a PostOnly LIMIT at
the touch (maker fee 0.02%) and is re-quoted up to 3 times over ~2.5 minutes;
only the unfilled remainder goes as a market order (0.055%). Every opening order
carries a stopLoss 8% away and passes `scripts/checks.py`. You cannot bypass the
gate, and must not try (no BYBIT_SKIP_GATE, no direct API calls for entries).

If an order is BLOCKED by the gate, that is the rail working: report it and move
on. After the orders, execute re-checks every position for a stopLoss and prints
`STOP PROBLEM:` lines if any is missing. If the script errors, run
`python scripts/v9.py status`, make sure every open position shows a stopLoss,
and report. Re-running `execute` for the same plan is safe: it cancels this
engine's resting orders and trades only the gap to the targets. Never leave a
perp position without a stop.

## 4. Record

    python scripts/v9.py status

Append 3–5 lines to `memory/V9-JOURNAL.md`: run time, what the strategy wanted,
what you decided and why, fills (maker share), P&L since v9 start. Then

    git add memory/V9-LOG.csv memory/V9-JOURNAL.md data/live/decisions.json data/live/brief.md
    git commit -m "v9 run <run_id>"
    git push origin main

Push straight to `main` (never a `claude/*` branch or a PR). If the push is
rejected because the remote moved, run `git pull --rebase origin main` and push
again. If it still fails (network), say so in the reply and move on - the commit
is safe locally and the next run pushes it. Never let a push problem delay or
change trading.

## Hard rails (enforced in code — for your information, not negotiation)

- Budget $200 (TRADING_BUDGET_USD). Leverage 5x. Margin ≤ 50% and gross
  notional ≤ 300% of budget. Stop inside half the liquidation distance.
- Daily realized loss ≥ 5% of budget → no new entries until 00:00 UTC.
- `HALT_TRADING` file at the repo root → no new entries at all. Exits always work.
